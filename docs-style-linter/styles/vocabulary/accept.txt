# Accepted vocabulary: proper nouns and initialisms that are correct as written.
#
# NOT Vale's `Vocab` mechanism, deliberately. Vale's accept.txt is a *global
# alert filter*: any alert whose match overlaps an accepted term is dropped,
# across every rule. Listing `API` there silently disabled the whole ApiKeyCase
# rule -- 49 real violations in this corpus stopped being reported, with no
# warning and no error. The fixture suite caught it; a production adoption
# would not have.
#
# So this file is consumed by tools/sync_vocab.py instead, which writes the
# terms into the `exceptions` list of the two rules that actually need them.
# Per-rule exceptions are scoped; a global suppression list is not.
#
# This file is the single source of truth for "words that are already spelled
# and capitalised correctly". `tools/sync_vocab.py` propagates it into the
# `exceptions` list of HeadingSentenceCase (so a product name in a heading is
# not mistaken for title case) and of Acronyms (a term in the accepted
# vocabulary is, by definition, one readers are expected to know).
#
# Maintaining this list *is* the adoption work. Measured on the vendored
# corpus, an empty vocabulary produced 167 HeadingSentenceCase alerts, almost
# all of them product names. A docs team's first week with this linter is spent
# here, not in the rule files.
#
# Deliberately excluded: generic English words that happen to appear inside a
# product name ("Search", "Cloud", "Index", "Server", "Desktop"). Exempting
# those would silence real title-case violations such as "Configure Your Search
# Settings".
